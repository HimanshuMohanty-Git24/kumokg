## Engineering decisions
1. **Packaging:** `skills/kumokg/pyproject.toml` is a hatchling package whose editable install adds `scripts/` to `sys.path` (`dev-mode-dirs`), so `core`, `studio`, `adapters` and `kumokg_cli` import identically whether run as `uv run --project skills/kumokg kumokg ...` or `python scripts/kumokg_cli.py ...`. The repo-root `pyproject.toml` is a virtual dev project that depends on the skill by path (plus the `[mcp]` extra) so `uv run pytest` works from the repo root. Nothing inside `skills/kumokg/` references paths outside it.
2. **Corpus inspection (`./data/`):** the folder is `Data/` and contains `Alice's Adventures In Wonderland.pdf` (80 pages, text layer, median 1,933 chars/page, no images) and `AliceInWonderLand.md` (Gutenberg plain text, 3,599 lines). The spec's "TXT" is this `.md` file; it has no frontmatter/wikilinks so it is routed as prose.
3. **Windows console:** stdout is cp1252, so the CLI reconfigures stdout/stderr to UTF-8 (`errors="replace"`).
4. **Boilerplate:** repeated per-page lines (site banner, bare page numbers) are stripped before chunking; character offsets refer to the cleaned page text, which is re-derivable from the source.
5. **Near-duplicate sources:** exact duplicates (same SHA-256, or word-shingle Jaccard >= 0.98) are excluded with an explicit reason; near-duplicates (Jaccard >= 0.5) are flagged and kept for cross-source corroboration unless `--dedup skip`. On `./data/` the `.md` is a 99.8% match of the PDF, so the PDF (page anchors) is primary and the `.md` is recorded as an excluded duplicate.
6. **Hatchling layout:** the wheel uses `sources = ["scripts"]` so `core/`, `studio/`, `adapters/` and `kumokg_cli.py` install top-level; `force-include` was dropped because it copied a stale CLI into site-packages even for editable installs.
7. **Structured relations** may carry `valid_from_field` / `valid_to_field` so table columns (e.g. `start_date`) become bi-temporal validity; relation rules support `inverse_cue_phrases` ("led by") for the heuristic extractor.
8. **Sampling budget:** two-thirds of `sample` slots go to beginning/middle/end chunks (round-robin over documents, largest first), one-third to high term-diversity chunks across modalities.
9. **Proposals:** the verifier groups candidates into edge proposals keyed by `(source_id, predicate, target_id, valid_from)`; Gate 2 decides proposals, not raw candidates. An undated claim of the same fact folds into a single dated version (e.g. a PDF sentence corroborating an XLSX row with `start_date`).
10. **Candidate identity** includes the extractor, so identical evidence observed by two extractors never overwrites another extractor's candidate (this fixed a real data-loss bug found by the determinism test).
11. **Perceptual hashing** uses a 16x16 (256-bit) dHash: 8x8 judged two different mostly-white scanned pages identical. Images dedupe at <= 10 bits, rendered pages at <= 3 bits.
12. **Caching:** `Workspace.load_chunks()` re-reads `chunks.jsonl` whenever its mtime/size changes, so long-running processes (Studio) never serve stale chunks.
13. **Quarantine is a hard guardrail:** `commit` refuses quarantined proposals even if a decision says approve; approved closed-world schema extensions are written back into `ontology.approved.json` and logged.
14. **Alice ontology & extraction:** the ontology draft (`tests/fixtures/alice/ontology_draft.json`) and 67 Tier-1 claims (`tests/fixtures/alice/harness_claims.jsonl`) were authored by the coding agent acting as the harness, every quote copied verbatim from the PDF; the offline heuristic extractor adds breadth. Deliberate Gate 2 material: 2 hallucinations (quarantined), 1 typo'd quote (soft-verified), 2 schema extensions, low-confidence heuristic co-occurrences and a functional `HAS_SIZE` contradiction.
15. **Narrative valid-time:** Alice's bi-temporal facts use the story's clock, the 'golden afternoon' of 4 July 1862 (`1862-07-04T14:05` ten inches high -> superseded at `14:30` by nine feet high via a live `patch supersede-edge`). `as_of` accepts dates or ISO datetimes (lexicographic ISO comparison).
16. **Commit keeps exact quotes:** proposal evidence is ordered verified-first and `commit` stores only verbatim-verified evidence whenever any exists, so every committed Alice edge is backed by an exact quote (fuzzy `soft_verified` evidence only enters the graph if a reviewer approves a soft-only proposal).
17. **Grounded examples** for Gate 1 skip title pages / tables of contents, match class aliases (e.g. `'DRINK ME'` for *Drink Me Bottle*) and are sentence-bounded verbatim spans (length-preserving fold so offsets stay exact).
18. **Explorer layout** is pre-settled synchronously on first load and auto-fitted, so the first frame is centred and readable without relying on animation frames.

19. **Studio v2 (industry-grade UI pass):** still zero-build vanilla ES modules + Canvas 2D, flat tokens, no new dependencies. Gate 1/Gate 2 are full-width workbenches (max 1560 px, Gate 2 full viewport height with independently scrolling panes); Explorer gets a health pill (Doctor scorecard popover), floating layout toolbar (Force / Radial with ring guides / Clusters, fit, edge labels), curved edges with arrowheads, collision-free pill labels, ego-graph focus, dashed superseded edges, dimmed zero-degree nodes, a bottom timeline with play/pause and a slide-over provenance drawer. All API changes are additive (`workspace_name`, `classes`, `audit.active`, `graph_edge`, `surfaces`, `open_conflict`, `POST /api/contradictions/resolve`, `/api/client-log`).
20. **Entity resolution is asymmetric:** a shorter mention may resolve to a longer canonical name ("Voss" -> "Elena Voss"), never the reverse, and a possessive of a known name ("Alice's Sister") is always a new entity. Proposals whose subject and object resolve to the same node are routed to review with a `self-loop` reason.
21. **Contradictions are judged against the graph:** each contradiction value is matched to its committed edge by proposal id, else by identical triple (edges added by a chat patch), so a value whose edge was superseded or retracted no longer counts as live. A bi-temporal `supersede-edge` patch therefore settles a functional conflict; Gate 2 offers Keep only this / Keep other / Keep both as temporal sequence (supersede) and, once settled, can attach the remaining proposal's evidence to the committed edge.
22. **Headless visual QA:** `?snapshot=1` disables SSE and animation (as does `prefers-reduced-motion`) so `msedge --headless --virtual-time-budget` captures settled frames; pages post render stats (labels drawn, overlaps) and uncaught errors to `/api/client-log`, which the QA loop reads back.
23. **Dual licensing (v1.0):** KumoKG is source-available under the PolyForm Noncommercial License 1.0.0 (canonical text, byte-exact, with a `Required Notice:` line) plus a paid commercial license (`COMMERCIAL_LICENSE.md`). The skill ships its own copies of both files so an installed skill stays self-contained. Package metadata uses the PEP 639 SPDX expression `PolyForm-Noncommercial-1.0.0` with `license-files` and no license classifiers (hatchling >= 1.27).
24. **Live-mode QA over CDP:** headless Edge is driven through the DevTools protocol from a dependency-free Node script (native `WebSocket`), so SSE stays on: it captures the README screenshots with the `Live` badge, checks DOM state (alias counts, hub labels, drawer rows) and times an Explorer refresh after a real `kumokg patch`.
25. **Hub nodes:** when the focused node has more than 12 incident edges, its predicate labels are not drawn on the canvas (the provenance drawer lists every relation); path labels and the explicit edge-label toggle still apply.
26. **Case-insensitive corpus folder:** tests resolve the real-world corpus folder as `data/` or `Data/`, so the suite passes on case-sensitive file systems without renaming the read-only folder.
